# Brainstorm Session: Mock Data for Demo App
Date: 2026-04-29

## Overview
The goal is to create a mock/simulation environment of the Mesh LilyGo Android App for a management demo. The mock version should simulate a Gateway and 6-8 NodeMeshes running live, sending telemetry data (GPS, battery, events) without requiring actual hardware. 

The user requested a separate source code directory/approach so it does not affect the main production codebase, allowing them to install this specific "demo" version on the phone.

## Capabilities & Scope
- **App Isolation**: The demo app should not interfere with the real app.
- **Node Simulation**: 6-8 mock nodes with moving GPS coordinates, battery life simulation, and network events.
- **Gateway Simulation**: The app acts as if it is connected to a Gateway that passes this node data.

## Phases
### Phase 1
- Establish a completely separate demo build variant or copied directory for the app.
- Implement a `MockDataSource` that generates fake protobuf/JSON serial data.
- Setup logic for 6-8 dummy nodes with basic randomized or predefined movement on the map.

### Phase 2
- Introduce scenario scripting (e.g. predefined events, alerts, message simulation) to make the demo more interactive.

## Open Questions
- Should we use Gradle Product Flavors (Demo vs. Live) with different application IDs so they can co-exist on the same phone, or physically duplicate the project folder? (Product Flavors are best practice, but user specifically asked for "1 thư mục mã nguồn riêng").
- What specific scenarios or node behaviors should we script for the demo?

## Next Steps

- Design the data simulation layer.

**Mô tả:** Đã bổ sung tính năng AI vào backend nhưng không thấy hiển thị và hoạt động trên UI.

**Root Cause (confirmed):**
- Backend AI routers ĐÃ được đăng ký đầy đủ trong `backend/app/main.py`:
  - `/api/ai` (pathfinding A*)
  - `/api/llm` (NLP chat — Ollama Phi-3/Llama-3)
  - `/api/vision` (mock YOLO detection)
- `frontend/src/App.tsx` CHỈ render 3 component: TacticalPanel, TacticalMap, EventLog
- **Không có frontend component nào** cho AI — zero UI wiring

**Ưu tiên fix:** Pathfinding UI (user choice)

### Lỗi 2 — Node Offline Vẫn Hiển Thị Trên Frontend

**Mô tả:**
- Tắt nodemesh TBEAM ID:1 → frontend vẫn hiển thị ID:1
- Bật nodemesh LORA32 ID:2 → frontend không thấy ID:2, vẫn chỉ thấy ID:1 đã tắt

**Root Cause (confirmed) — 3 tầng thiếu filter:**

| Tầng | File | Vấn đề |

## Phân Tích Kỹ Thuật

### Fix Lỗi 2 — Stale Node Filter

**Approach đơn giản nhất:** Filter tại tầng UI (TacticalPanel.tsx)

```typescript
const STALE_THRESHOLD_MS = 15_000; // 15 giây

const activeNodes = nodeList.filter(node => {
  const lastSeen = new Date(node.last_seen).getTime();
  return Date.now() - lastSeen < STALE_THRESHOLD_MS;
});
```

**Tại sao chọn tầng UI?**
- Không phá vỡ store state (các component khác có thể cần history)
- Đơn giản, dễ kiểm soát threshold
- TacticalMap cũng cần filter tương tự (marker trên bản đồ)

**Cần áp dụng ở:**
1. `TacticalPanel.tsx` — danh sách node bên trái
2. `TacticalMap.tsx` — marker trên bản đồ (cần verify)

### Fix Lỗi 1 — Pathfinding UI

**Backend đã có:** `POST /api/ai/pathfinding` → nhận `{start, end, danger_zones}` → trả GeoJSON LineString

**Frontend cần thêm:**
- Click mode trên TacticalMap: click điểm 1 (start), click điểm 2 (end) → gọi API

**Phát hiện quan trọng:** `TacticalMap.tsx` đã có sẵn layer `ai-path` (màu xanh) — chỉ cần wiring logic click + API call.

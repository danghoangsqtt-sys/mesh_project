# Task 6.2: Remote Node Config

## Objective
Allow the Android application to send remote configuration commands to soldier nodes to change their LoRa parameters (Spreading Factor, Bandwidth, Frequency) dynamically. The soldier nodes should save these configurations to non-volatile storage (NVS) using the `Preferences` library and apply them without requiring a re-flash.

- `e:\data\MyProject\2026\firmware_mesh_lilygo\soldier_node_production\include\config.h`
- `e:\data\MyProject\2026\firmware_mesh_lilygo\soldier_node_production\src\lora_manager.cpp`
- `e:\data\MyProject\2026\firmware_mesh_lilygo\soldier_node_production\src\main.cpp`
- `e:\data\MyProject\2026\mesh_lilygo_app_android\app\src\main\java\com\meshcommand\app\ui\tactical\CommandPanel.kt`

## File-Level Plan

1. **Firmware (`soldier_node_production`)**:
   - Change `config.h` variables from `constexpr` to normal `extern` variables.
   - Use `Preferences` to load config from NVS on boot in `main.cpp`.
   - Update `lora_manager.cpp` to intercept commands starting with `CFG:SF=9` or `CFG:BW=125` etc.
   - Update the variables, save them to NVS, and call `LoRaManager::begin()` to apply the new settings.

2. **Android App (`mesh_lilygo_app_android`)**:
   - Update `CommandPanel.kt` to include a small drop-down or dialog for Remote Node Config.
   - User can select Spreading Factor (7-12) and transmit a `CFG:SF=X` command to the targeted node.

## Best Practices
- Follow Android Material Design for the configuration UI.
- Handle firmware `Preferences` carefully (commit only when changed) to preserve flash memory lifespan.

# Task 6.3: OTA Firmware via Gateway

## Objective
Implement a mechanism to upload `.bin` firmware files to the Soldier nodes over the LoRa network via the Gateway. Since LoRa bandwidth is extremely low, this requires chunking the firmware into 24-byte payloads inside the 32-byte `CommandPacket`.

## File-Level Plan

1. **Firmware (`soldier_node_production`)**:
   - Create `ota_handler.h` and `ota_handler.cpp` wrapping the Arduino `<Update.h>` library.
   - In `lora_manager.cpp`, if `msg` starts with `OTA:START:` we call `Update.begin()`.
   - If `msg` starts with `OTA:DAT:`, parse the chunk and write to `Update`.
   - If `msg` starts with `OTA:END:`, we call `Update.end()` and `ESP.restart()`.

2. **Android App (`mesh_lilygo_app_android`)**:
   - Create `OtaManager.kt` to handle reading a `.bin` file, slicing it into chunks, and tracking the upload progress.
   - Update `CommandPanel.kt` or create a new `OtaDialog.kt` UI component to let users select a mock firmware file and start the OTA process. (For now, we can just simulate sending dummy OTA chunks or select a small dummy file to prove the protocol works).

## Best Practices
- Chunking must be robust. LoRa drops packets. We need to handle sequence IDs or at least acknowledge each chunk (or use a fire-and-forget broadcast with high redundancy). For this milestone, a simple linear broadcast with delay will suffice to demonstrate the protocol.

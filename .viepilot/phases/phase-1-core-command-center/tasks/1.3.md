# Task 1.3 — USB OTG Serial Manager

## Objective
Implement USB Serial communication manager sử dụng thư viện `usb-serial-for-android` (mik3y). Manager phải auto-detect ESP32 T-Beam qua VID/PID, kết nối 115200/8N1, bridge serial bytes thành Kotlin `callbackFlow`, xử lý USB attach/detach intents, và hỗ trợ reconnect khi USB bị rút rồi cắm lại.

## Paths
- `app/src/main/java/com/meshcommand/app/comm/UsbSerialManager.kt`
- `app/src/main/java/com/meshcommand/app/comm/ConnectionState.kt`
- `app/src/main/res/xml/device_filter.xml`

## File-Level Plan
1. **ConnectionState.kt**:
   - Sealed class cho trạng thái kết nối: `Disconnected`, `Connecting`, `Connected(deviceName)`, `Error(message)`.
   - Được expose ra UI qua StateFlow.

2. **UsbSerialManager.kt**:
   - `findDevice()` — Scan USB devices qua `UsbManager`, filter theo VID/PID (CP210x: 0x10C4/0xEA60, CH340: 0x1A86/0x7523).
   - `connect(device)` — Open USB device, tạo `UsbSerialPort`, cấu hình 115200/8N1 và bắt đầu đọc.
   - `disconnect()` — Close port, cleanup resources.
   - `serialDataFlow(): Flow<ByteArray>` — `callbackFlow` bridge: serial read callback → emit ByteArray chunks.
   - `connectionState: StateFlow<ConnectionState>` — Expose trạng thái kết nối.
   - `write(data: ByteArray)` — Gửi dữ liệu xuống Gateway qua serial.
   - USB permission request handling via `BroadcastReceiver`.
   - USB attach/detach `BroadcastReceiver` — auto-reconnect khi USB cắm lại.
   - Mock mode (`MOCK` flag) cho development không có phần cứng.

3. **device_filter.xml**:
   - USB device filter cho CP210x (VID=0x10C4, PID=0xEA60) và CH340 (VID=0x1A86, PID=0x7523).

## Best Practices
- Sử dụng `callbackFlow` thay vì LiveData để bridge serial → coroutine world.
- `awaitClose {}` đảm bảo cleanup khi Flow bị cancel.
- Không giữ Context reference trực tiếp, nhận qua constructor/Hilt.
- USB operations chạy trên `Dispatchers.IO`.
- Reconnect với backoff delay.

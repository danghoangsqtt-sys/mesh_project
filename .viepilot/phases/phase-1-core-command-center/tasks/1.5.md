# Task 1.5 — Data Layer (Room DB + Repository)

## Objective
Implement Room database entities, DAOs, database class, và Repository pattern cho soldier data. Repository bridge giữa serial data (từ ForegroundService SharedFlow) và Room DB, bao gồm node timeout logic (30s → offline) và alert level calculation.

## Paths
- `app/src/main/java/com/meshcommand/app/data/entity/SoldierEntity.kt`
- `app/src/main/java/com/meshcommand/app/data/entity/EventEntity.kt`
- `app/src/main/java/com/meshcommand/app/data/dao/SoldierDao.kt`
- `app/src/main/java/com/meshcommand/app/data/dao/EventDao.kt`
- `app/src/main/java/com/meshcommand/app/data/MeshDatabase.kt`
- `app/src/main/java/com/meshcommand/app/data/SoldierRepository.kt`
- `app/src/main/java/com/meshcommand/app/di/AppModule.kt` (modify — add DB/DAO/Repo providers)

## File-Level Plan
1. **SoldierEntity.kt** — Room `@Entity(tableName="soldiers")` với PrimaryKey `nodeId`, tất cả trường theo schema SQL. Bao gồm companion `fromPacket(SoldierPacket): SoldierEntity` converter.
2. **EventEntity.kt** — Room `@Entity(tableName="events")` với autoGenerate PrimaryKey, eventType enum string, severity levels.
3. **SoldierDao.kt** — `@Dao` interface: `@Upsert`, `@Query getAll(): Flow<List<SoldierEntity>>`, `@Query getByNodeId(nodeId): Flow<SoldierEntity?>`, `@Query getOnlineSoldiers()`, `@Query markOffline(thresholdMs)`.
4. **EventDao.kt** — `@Dao` interface: `@Insert`, `@Query getRecentEvents(limit)`, `@Query getEventsForNode(nodeId)`.
5. **MeshDatabase.kt** — `@Database(entities=[SoldierEntity, EventEntity], version=1)`, abstract DAOs.
6. **SoldierRepository.kt** — `processPacket(SoldierPacket)`: convert → upsert DB + calculate alert level + log events. `checkTimeouts()`: mark offline nếu lastSeen > 30s. Expose `allSoldiers: Flow`, `recentEvents: Flow`.
7. **AppModule.kt** — Thêm `@Provides` cho `MeshDatabase`, `SoldierDao`, `EventDao`, `SoldierRepository`.

## Best Practices
- Room `@Upsert` cho insert-or-update logic.
- Flow return type từ DAO cho reactive updates.
- Repository chạy DB operations trên `Dispatchers.IO`.
- Alert level: 0=OK, 1=WARN (low battery/sensor error), 2=CRIT (man down/SOS/critical battery).
